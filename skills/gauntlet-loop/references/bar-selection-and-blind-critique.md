# The Bar Selection & Blind Critique Protocol

> **Core Axiom**: *The bar is the whole trick. Everything else in a gauntlet loop is scaffolding. The loop only produces quality if the thing it compares against is real.*

---

## 1. The Three Tests of a Valid Bar

A gauntlet loop reference must satisfy three non-negotiable criteria before round 1 begins:

| Test | Requirement | Example Passing | Example Failing |
| :--- | :--- | :--- | :--- |
| **1. Named** | A specific entity, not a vague abstract category. | "Stripe's billing pricing page" | "Award-winning modern SaaS pricing pages" |
| **2. Fetchable** | The critic can obtain the raw reality — screenshot it at the same viewport, read the published text, run the test suite, or inspect the repo. | Live URL with Playwright screenshot at 1440px | Behind an inaccessible login or hallucinated memory |
| **3. Comparable** | Both artifacts can sit side-by-side so a judge can pick a winner. | Two 2,000-word essays or two mobile navbar renders | Comparing a CLI tool against a marketing website |

---

## 2. Bars by Goal Type Matrix

| Goal Type | Concrete Passing Bar | Measurable Half |
| :--- | :--- | :--- |
| **Web Apps & UI** | Live site of a named best-in-class product, screenshotted at identical viewports (375px & 1440px). | Zero layout shift, CSP/HSTS headers, zero horizontal scroll overflow. |
| **Code & CLI Tools** | Implementation from a top-tier open-source repository (e.g. Bun, Ripgrep, Hono). | Benchmark latency, memory footprint, 100% test pass rate. |
| **Writing & Essays** | A specific published article by a named author (e.g. Julia Evans, Paul Graham). | Reading grade level, clarity score, word count parity. |
| **System Research** | A named industry whitepaper or peer-reviewed methods section. | Citation count, empirical receipts, falsifiable claims. |
| **Visual / 3D Design** | Uncompressed screenshots or video footage from a named shipped production title. | Frame rate, asset draw calls, contrast ratios. |

---

## 3. Blind A/B Critique Protocol

Self-grading by the builder agent is strictly forbidden. The *Fresh Critic* must evaluate work blindly:

1. **Strip Labels**: Remove branding, author names, and indicators of which version was generated by the builder vs which is the reference bar.
2. **Side-by-Side Comparison**: Present Artifact A and Artifact B under identical inspection conditions.
3. **Objective Choice**: The critic must state unequivocally:
   - Which artifact is better and why.
   - The single biggest remaining gap between ours and the bar.
4. **No Empty Flattery**: Praise is considered noise; actionable critiques focus exclusively on the #1 biggest fix for the builder's next iteration.
