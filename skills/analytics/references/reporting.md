# reporting — Reporting: recurring performance reports that end in decisions.

## Intake

- Audience (client, exec, team) and their questions
- KPIs, targets, and prior-period baselines
- Data sources and reporting cadence
- Format (deck, doc, dashboard link)
- Default stack: Looker Studio for the recurring view; else any scheduled report format on available sources.

## Deliverable

A performance report: headline result vs target, KPI scorecard with trend, wins and misses with causes, channel/pillar breakdown, and a prioritized action list for next period.

## Procedure

1. Lead with the headline result against target — the answer, not the preamble.
2. Show the KPI scorecard with prior-period movement.
3. Explain wins and misses with causes, not just restated numbers.
4. Break down by channel/campaign/pillar so the reader sees where it came from.
5. End with a prioritized action list and the owner of each.
6. Keep a consistent structure month over month so trends read quickly.
7. Archive each report so history is comparable.
8. Triage anomalies by sensitivity tier (watch/alert/act); pass only severity-gated items to action.
9. Read retention as a cohort matrix — floor rate, stabilization point, payback period, LTV — not a single-period average.
10. Score churn risk on a 4-tier signal scorecard weighted by LTV-at-risk; model 2-3 budget-reallocation shifts, flag declining returns, and check CPA against LTV before moving spend.
11. Define every KPI as name/definition/method/source/target/frequency/owner; hold 3–5 primary metrics balancing behavioral (completion, error rate, adoption) with attitudinal (SUS/NPS/CSAT); set baselines before measuring change.
12. Before hypothesizing from a surprising number, rule out artefacts: event definition vs label, denominator shift, unenforced funnel order, deploy/holiday/campaign overlap, hidden platform split.
13. When data and interviews conflict, route each question to its source (what/how-many/where → data; why/intent → research); pre-register what result would kill each account; never average both into a compromise.

## Quarterly executive (QBR) cut

Same playbook on a quarterly cadence for executive review: headline result vs quarterly target, KPI scorecard with prior-quarter trend, wins and misses with causes, a risk register (risk, owner, mitigation, date), and a next-quarter plan (action, owner, date). Write the client-language cut execs actually read; archive each quarterly report so quarters stay comparable.

Boundary: meeting decisions are not logged here — route to retain qbr.

## Quality gate

- [ ] Headline result vs target leads.
- [ ] KPIs shown with prior-period trend.
- [ ] Each win/miss explained with a cause.
- [ ] Breakdown by channel/campaign.
- [ ] Action list prioritized with owners.
- [ ] Anomalies triaged by tier; only severity-gated items actioned.
- [ ] Retention read as cohort matrix with floor/stabilization; churn scored 4-tier by LTV-at-risk.
- [ ] Reallocation scenarios (2-3) checked for declining returns and CPA-vs-LTV.
- [ ] KPIs carry full definitions with baselines; artefacts ruled out before hypotheses; data/research conflicts resolved by source, not averaged.
- [ ] Quarterly cut shows prior-quarter trend, a risk register (owner/mitigation/date), and a next-quarter plan (owner/date).

## Routing

- Deep instrumentation or event-definition work → tracking mode.
- Meeting decisions → retain qbr.
