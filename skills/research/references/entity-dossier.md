# entity-dossier — Hypothesis-forced due-diligence dossier.

## Scope

- The entity (company, person, vendor, partner, acquirer, client) and the decision (trust, partner, buy, hire, deal).
- The concrete hypothesis about them that the dossier must test (e.g. "is a credible long-term partner", "is financially healthy").

## Gather — hypothesis first

1. State the hypothesis up front in writing. This is the anti-confirmation-bias gate.
2. For each claim you form about the entity, find a test: registry/financial filings, reviews, case history, founder/leadership track record, legal/litigation, community reputation, security posture.
3. Record provenance (URL, date, source type) for every material claim.

## Synthesize

1. Verdict on the stated hypothesis: CONFIRMED / PARTIAL / REFUTED / UNVERIFIABLE, with the evidence for and against.
2. 12-month activity timeline (launches, hires, funding, legal, churn signals).
3. Red flags with severity and owner path (who must review before acting).
4. Conversation hooks / open questions for a live call.
5. Source-provenance audit: what is verifiable, what is stale, what is claimed without source.

## Quality gate

- [ ] Hypothesis stated before evidence gathered.
- [ ] Verdict is CONFIRMED/PARTIAL/REFUTED/UNVERIFIABLE, never vague.
- [ ] Every material claim cited (URL + date).
- [ ] Red flags have severity and a named review owner.
- [ ] Confirmation-bias check: evidence against the hypothesis is presented, not buried.

## Routing

- Deal/pricing decisions from this → `growth` / `ops`.
- Claims log → `evidence-ledger`.
