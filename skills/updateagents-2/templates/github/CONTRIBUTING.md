## Contribution process

1. Open an issue or discuss a substantial change before implementation.
2. Keep each pull request focused on one coherent change and follow the repository's established branch and commit workflow.
3. Include the reason for the change, its scope, and verifiable test/build evidence in the pull request.
4. Update the changelog and relevant documentation when behavior or user-facing contracts change.
5. Never include credentials, private user data, or generated secrets in commits.

Ask the project owner when a contribution rule or project-specific command is not documented; do not invent one.
