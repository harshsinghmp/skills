# Memory File Priority System

## Priority Order (highest to lowest)

1. **AGENTS.md** - Universal agent memory file (preferred)
2. **CLAUDE.md** - Claude-specific instructions
3. **.cursorrules** - Cursor IDE rules
4. **.github/copilot-instructions.md** - GitHub Copilot instructions
5. **GEMINI.md** - Gemini-specific instructions
6. **CODEX.md** - Codex/CLI-specific instructions
7. **Any root-level *.md with agent-related name** - Fallback

## Selection Logic

When multiple files exist:
- Use the highest priority file for updates
- Never create duplicates at lower priority if higher exists
- If updating AGENTS.md, check if CLAUDE.md should be symlinked or merged
- Preserve all existing files unless explicitly told to consolidate

## File Size Guidelines

- **Ideal**: 2-5KB
- **Maximum**: 10KB (warn user if approaching)
- **Critical sections only**: Commands, architecture, gotchas
- **Avoid**: Full API docs, exhaustive type definitions, complete test suites

## Content Freshness

Mark sections with timestamps when possible:
```markdown
## Testing (updated 2026-08-16)
- Framework: Vitest
- Command: `npm test`
- Location: `src/**/*.test.ts`
```

## Merge Strategy

When updating existing files:
1. **Preserve structure** - Don't reorder existing sections
2. **Add new sections** - Only if genuinely new information
3. **Update stale info** - Replace outdated commands/patterns
4. **Remove deprecated** - Delete sections marked as obsolete
5. **Deduplicate** - Remove redundant information

## Workspace Boundary Rules

- **Root detection**: Use `pwd` to determine workspace root
- **No parent traversal**: Never read/write above current directory
- **Subdirectory support**: Can update files in subdirectories if they exist
- **Multiple workspaces**: Each workspace maintains its own memory files

## Integration with Memory Tools

### cavemem
- Extracts compressed session history
- Provides historical context for changes
- Format: Markdown with timestamps

### codegraph  
- Maps code relationships automatically
- Identifies architectural patterns
- Format: Structured markdown with dependency graphs

### rtk
- Repository-level pattern extraction
- Command discovery and validation
- Format: JSON or markdown reports

### memoryagent
- Captures workspace-specific decisions
- Tracks learned conventions over time
- Format: Typed memory entries

### ponytail
- Recent activity extraction
- Log-based context gathering
- Format: Timestamped event streams
