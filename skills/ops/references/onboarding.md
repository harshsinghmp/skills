# onboarding — Onboarding: clean intake, isolated workspace, and a kickoff plan.

## Intake

- Client name, contacts, and communication preferences
- Engagement scope and start date
- Access needed (accounts, brand assets, credentials handled securely)
- Success criteria and key dates
- Default stack: Twenty/NocoBase/Odoo client record and Bitwarden credential handover where available, else any CRM/vault or secure notes.

## Deliverable

An onboarded client: an isolated, clearly named workspace, a populated intake record (contacts, scope, success criteria), access checklist, and a kickoff agenda.

## Procedure

1. Create an isolated client workspace (via `new-project` client mode) named consistently.
2. Record intake: contacts, scope, success criteria, key dates, comms preferences.
3. Run an access checklist: brand assets, analytics, ad accounts, CMS — collected securely.
4. Confirm scope and start date in writing before work begins.
5. Schedule and run a kickoff; capture decisions and next steps.
6. Set the communication cadence and reporting rhythm.
7. Log the engagement in the portfolio tracker.
8. Run the checklist spine: discovery questionnaire, then stakeholder RACI, then platform access, then knowledge-transfer session, then first-week plan.
9. Solo operator: you hold every RACI role — the map collapses to you + the client; kickoff becomes a written intake doc the client confirms async.

## Quality gate

- [ ] Workspace isolated and consistently named.
- [ ] Intake record complete (contacts, scope, criteria).
- [ ] Access collected securely.
- [ ] Scope and start date confirmed in writing.
- [ ] Kickoff held; decisions captured.
- [ ] Checklist spine complete: questionnaire, RACI, access, knowledge-transfer, first-week plan.
