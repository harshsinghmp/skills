# 3d — Interactive 3D Web Scenes, Spline & Asset Optimization

> **Operating Principle**: 3D on the web should elevate spatial storytelling and product tangibility without destroying page performance, frame rates, or mobile battery life. Keep assets strictly optimized (<2MB target), leverage progressive loading with fallback posters, and enforce a strict 60fps budget.

---

## 3D Tech Stack & Decision Matrix

| Tool / Framework | Best For | Typical Asset Format | Integration Method |
| :--- | :--- | :--- | :--- |
| **Spline** | Interactive landing page hero scenes, micro-interactions, responsive 3D UI | `.splinecode` / URL embed | `@splinetool/react-spline` or `<spline-viewer>` |
| **Three.js / React Three Fiber** | Custom shader effects, procedural geometry, complex scene graphs, game-like UIs | `.glb` / `.gltf` | `@react-three/fiber` + `@react-three/drei` |
| **Blender** | High-fidelity asset modeling, UV unwrapping, topology retopology, baking lights | Export to `.glb` / `.gltf` | Pre-processing pipeline with Draco compression |

---

## Asset Optimization & Compression Protocol (Blender → Web)

Before any 3D asset is embedded on the web, execute this hardening checklist:
1. **Polygon Budget**:
   - Hero 3D focal object: $\le 50,000$ triangles.
   - Background / decorative assets: $\le 10,000$ triangles.
2. **Texture Optimization**:
   - Use WebP or KTX2/Basisu GPU-compressed textures.
   - Maximum texture resolution: 2048x2048 for hero objects, 1024x1024 or 512x512 for secondary materials.
3. **Draco Geometry Compression**:
   - Apply Draco or meshopt compression via `gltf-pipeline` or `gltfpack`:
   ```bash
   gltfpack -i model.glb -o model.optimized.glb -c -cc
   ```
4. **Target File Sizes**:
   - Primary Hero Scene: $\le 2.5\text{MB}$ total.
   - Micro-interaction / icon 3D: $\le 500\text{KB}$.

## React Three Fiber (R3F) Clean Implementation Pattern

```tsx
import { Canvas } from "@react-three/fiber";
import { OrbitControls, useGLTF, Float, Environment } from "@react-three/drei";
import { Suspense } from "react";

function Model({ url }: { url: string }) {
  const { scene } = useGLTF(url);
  return (
    <Float speed={2} rotationIntensity={0.5} floatIntensity={0.8}>
      <primitive object={scene} scale={1.5} />
    </Float>
  );
}

export function HeroScene3D() {
  return (
    <div className="relative w-full h-[500px] md:h-[650px] overflow-hidden">
      {/* Fallback image shown during WebGL initialization or on low-end devices */}
      <Suspense fallback={<div className="w-full h-full bg-neutral-900 animate-pulse rounded-2xl" />}>
        <Canvas camera={{ position: [0, 0, 5], fov: 45 }} dpr={[1, 2]}>
          <ambientLight intensity={0.7} />
          <directionalLight position={[10, 10, 5]} intensity={1.2} />
          <Model url="/models/product.optimized.glb" />
          <Environment preset="city" />
          <OrbitControls enableZoom={false} enablePan={false} autoRotate autoRotateSpeed={1.0} />
        </Canvas>
      </Suspense>
    </div>
  );
}
```

## Performance Guardrails & Fallbacks

- **Power Preference**: Always declare `powerPreference: "high-performance"` on WebGL renderer.
- **DPR Clamping**: Restrict Device Pixel Ratio to `[1, 2]`; never render at 3x DPR on mobile (drastically drops frame rate).
- **Reduced Motion**: Respect `prefers-reduced-motion: reduce` by freezing continuous camera rotations and floating animations.
- **Graceful WebGL Failure**: Detect WebGL support; if WebGL fails or context is lost, render an optimized static WebP render or video loop.
